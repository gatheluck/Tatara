# verify — 空白を壊しにいく

まず `${CLAUDE_PLUGIN_ROOT}/reference/principles.md` を読むこと。

対象: $ARGUMENTS（省略時は尋ねる）。`synthesis.md` と `synthesis/S4-*.md` を読む。

## この工程の目的

**空白が本物かを確かめる。壊れたら成功。**

壊れるたびに主張が具体的になり、根拠が自分の判断から**他人の引用**に移る。
壊れなかった空白より、**何度か壊れて残った空白のほうが強い**（原則 11）。

## 立てるもの

### 1. 空白を壊す（本丸）

**見つけることを目標にさせる。** 「無いことを確認する」ではない。

- **Stage 3 と同じクエリを使わせない。** 同じ結果しか出ない
- **別の語彙・別の DB・別分野の呼び方**で探す
- 動詞も変える（transfer / propagate / migrate / lift / associate / link / bind / ground …）

> ⚠️ **凝った言い換えは効かないことが多い**（実測）。
> 平凡で直接的な語で**別のデータベース**を叩くほうが当たる。語彙探索に時間をかけすぎない。

被覆行列で**配置不能だった研究**があれば、一次情報で確定させる。配置できれば空白が埋まる。

### 2. 探索されていなかった領域

S4 が挙げたもの。特に:

- **特許** — 論文が無いのに製品機能がある技術は、特許にある。
  ただし Espacenet / J-PlatPat / WIPO は**静的取得では使えない**ことが多い。
  Google Patents は**十数クエリで IP ブロック**される。**代表 1 件で先に検査する**
- **非英語文献** — 用語の実在確認をしただけで出てくることがある。
  英語圏で「薄い」時代が、別言語では最も厚いことがある
- 規格文書、学位論文、企業技報

### 3. 未読の一次情報を回収する ★優先度は最上位

**数値だけが引用されて本文が読まれていないもの。** これが解けないと現在地の表が確定しない。

確定させること:
- **その数値は何のデータで測られたか。合成か実データか**（原則 8）
- 前提条件（何が入力として与えられているか）
- **著者自身が書いた限界**（原文引用）

購読壁は `principles.md` の「一次情報を取りにいく手引き」を試す。
**「全経路失敗」と報告されたものが別経路で取れた実例が複数ある。**

### 4. 機械的照合

議論ではなく照合で決着するもの。

| 対象 | やり方 |
|---|---|
| 引用 | 実在するか、内容が主張と合っているかを逐語照合 |
| コード | 実際に走らせる |
| 数値 | 再実行して再生成する |
| 矛盾 | 一次情報で確定させる |

**技術的な争点が残っているなら `/research-scope:spike`。議論では決着しない。**

## 各エージェントに課すこと

- **見つけることを目標にするが、無いものを在ると書かない**
- 検索した語と DB を**実文字列で全部記録**する（空白を主張するために必要）
- 取得できなければ「**取得不可**」と**経路ごとの結果**を書く。憶測で埋めない
- **本文を読めたのか、抄録のみかを 1 件ずつ明記**（原則 3）
- **WebSearch は 200 回で尽きる。** 難物は対象を絞る
- **Write で骨子 → Edit で追記、1 回 100 行以内**

## 出力先

`verify/` 配下にエージェントごとに別ファイル。

## 終わったら

`synthesis.md` を**更新する**。壊れた空白は訂正記録に移し、残ったものを主張として書き直す。

**主張が書き換わったこと自体を記録に残す。** 何版目かが分かるように。

そのうえで**人間が判断する。** 研究の方向を決めるのはここではない。
